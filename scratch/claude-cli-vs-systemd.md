# braid unlock: CLI-only vs CLI+systemd

## Option 1: Pure CLI (`braid unlock`)

Happy path:

1. Read `/etc/braid/config.json` — know which disks exist
2. For each disk: check if `/dev/mapper/braid-<key>` already exists → skip if so
3. For each disk: check if `by_id` path exists → skip missing (unplugged) disks
4. If any disks need opening: prompt for passphrase once
5. `cryptsetup open` each one with that passphrase
6. `btrfs device scan`
7. `mount /mnt/storage` (with `degraded` if not all disks present)

Design questions:

- **Wrong passphrase** — try the first disk, if it fails, bail immediately with a clear error? Or prompt again (max N retries)?
- **Already fully unlocked+mounted** — print "pool already available" and exit 0? Or treat as error?
- **Partial state** (some open, some not, not mounted) — just pick up where things left off. Falls out naturally from skip logic.
- **Mount included or separate?** — lean toward including it. Unlocking LUKS without mounting is useless 99% of the time. `braid lock` (future inverse) would unmount+close.
- **Output style** — per-disk status lines like doctor, e.g. `[ok] aaa unlocked`, `[skip] bbb not found`, `[ok] ccc unlocked`, `[ok] mounted /mnt/storage`

## Option 2: CLI + systemd hybrid

Dependency chain:

```
braid unlock (CLI, interactive)
  → opens LUKS, scans btrfs
  → systemctl start braid-pool.target
      → mnt-storage.mount activates
          → user services (plex, samba, etc.) activate
```

Systemd units:

```ini
# mnt-storage.mount (generated by NixOS from fileSystems)
[Mount]
What=/dev/mapper/braid-aaa
Where=/mnt/storage
Type=btrfs
Options=degraded
```

```ini
# braid-pool.target
[Unit]
Description=braid storage pool is ready
Requires=mnt-storage.mount
After=mnt-storage.mount
```

```ini
# User's service (e.g. plex, samba, whatever)
[Unit]
After=braid-pool.target
BindsTo=braid-pool.target
# BindsTo = stop plex if pool goes away
```

`braid unlock` CLI does:

1. Prompt for passphrase (interactive tty — the part systemd is bad at)
2. `cryptsetup open` each detected disk
3. `btrfs device scan`
4. `systemctl start braid-pool.target` — kicks the mount + everything downstream

`braid lock` (inverse) would be:

1. `systemctl stop braid-pool.target` — cascades: stops dependent services, unmounts
2. `cryptsetup close` each volume

Key insight: **CLI owns the interactive passphrase part**, systemd owns the **dependency graph**. Each does what it's good at. NAS users get `BindsTo=braid-pool.target` on their services.
