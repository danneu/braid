# Plan: Move disk membership from Nix config to CLI-owned runtime state

## Context

`braid.disks` in Nix config declares which disks are in the pool, but disk membership
is operational state ("which drives are in my pool right now"), not system architecture
("what services should run on this machine"). Requiring `nixos-rebuild` to add a drive
is wrong. This change moves disk membership to a CLI-owned runtime state file and
removes `braid.disks` from the Nix module entirely.

braid is unreleased — no backwards compatibility, no migration paths, no fallbacks.

## Architecture

### State model

**`/var/lib/braid/pool.json`** — authoritative membership (NEW, replaces config.disks)
```json
{ "disks": { "toshiba": "/dev/disk/by-id/ata-TOSHIBA_...", "wd": "/dev/disk/by-id/ata-WDC_..." } }
```
- Pre-commit writes: mutating commands persist new membership BEFORE the irreversible
  disk operation. If persist fails, abort before touching the disk.
- Atomic writes via `state_io.rs` (temp file, fsync, rename, fsync parent).
- `unlock` requires this file to exist and be valid. If missing or corrupt, `unlock` fails
  with a clear error directing the user to `braid discover --write`.

**`/var/lib/braid/disk-map.json`** — advisory observed metadata (EXISTING, unchanged)
- Best-effort writes, never fail the primary operation.
- Tracks luks_uuid, devid, added_at. Reconstructable from live pool + LUKS headers.

**`/etc/braid/config.json`** — machine config (SIMPLIFIED)
```json
{ "mount_point": "/mnt/storage" }
```
- No disk information. Just mount point.

### Lifecycle model

```
braid-pool.target          start handle — wants unlock only, NOT braid-online
braid-unlock.service       manual passphrase path
braid-auto-unlock.service  USB keyfile path
braid-online.service       lifecycle owner (ExecStop=braid lock, RemainAfterExit=yes)
mnt-storage.mount          readiness contract (auto-generated by systemd from /proc/mounts)
consumers                  After= + BindsTo= mnt-storage.mount
```

Only successful unlock paths start braid-online (via wrapper's `mountpoint -q` check).
The target does NOT start braid-online. This ensures "braid-online active" = "pool mounted."

**Consumer dependency contracts**:
- Oneshot/periodic services (monitor, scrub): `After=mnt-storage.mount` + `BindsTo=mnt-storage.mount`.
  They don't hold the filesystem busy, so unmount ordering doesn't matter.
- Long-running services that hold open files (e.g. samba, nfs): must additionally use
  `After=braid-online.service` + `BindsTo=braid-online.service` so systemd stops them
  before `braid lock` runs `ExecStop`, preventing unmount failures from busy filesystems.

### Mutation ordering

All mutating commands: validate → persist membership to pool.json → irreversible disk op → disk-map update.

### State contract

- `pool.json` is authoritative. `unlock` requires it.
- `unlock` is read-only with respect to pool.json. It never writes, creates, or repairs it.
- If pool.json is missing or corrupt, `unlock` fails with:
  `"pool membership not found — run 'braid discover --write' to create it"`
- If pool.json is readable but stale (a member fails to probe), `unlock` warns and
  proceeds with the members it can probe. It never rewrites pool.json.
- Only these commands write pool.json: `braid add`, `remove`, `replace`, `remove-missing`,
  `braid discover --write`.

### Recovery

Recovery is always explicit, never implicit:
- `braid discover` scans `/dev/disk/by-id/*` for LUKS devices with `braid-*` labels.
  Displays what it finds. With `--write`, persists to pool.json.
- This is a repair tool, not a bootstrap mechanism. The normal path to create pool.json
  is `braid add`.

## Commits

### Commit 1: CLI refactor — runtime membership

One commit: add membership.rs + discover.rs, cut all commands to pool.json, change
add/replace syntax, strip disks from config.rs. Everything in one shot.

#### New: `cli/src/membership.rs`

```rust
pub struct PoolMembership {
    pub disks: BTreeMap<String, ByIdPath>,
}
```

- `save_membership(m: &PoolMembership) -> Result<(), MembershipError>` — fail-hard atomic write
- `load_membership() -> Result<PoolMembership, MembershipError>` — NotFound | Corrupt | Ok
- `pub fn is_valid_disk_name(name: &str) -> bool` — extracted from config.rs
- `validate_no_conflicts(existing: &PoolMembership, name: &str, by_id: &str) -> Result<()>`:
  - Reject if name exists with a different by_id (reassignment)
  - Reject if by_id exists under a different name (rename)
  - Same invariant as the old `validate_config_name_stability`, expressed directly
    against the single source of truth

#### New: `cli/src/discover.rs`

`discover_pool_members(runner)`:
1. Scan `/dev/disk/by-id/*` (skip `-part[0-9]+$`)
2. `cryptsetup isLuks` each
3. Read LUKS label — if `braid-<name>`, record it
4. Return `BTreeMap<String, ByIdPath>`

#### New: `braid discover` command

Explicit repair tool only. Not called automatically by any other command.
- Displays discovered labeled LUKS devices
- `--write`: persist to pool.json (fail-hard)
- `--dry-run`: show without writing

#### All command files — read membership, not config

| File | Change |
|------|--------|
| `unlock.rs` | Load membership — fail if missing/corrupt. Iterate membership.disks for LUKS probe + mount key. If a member fails to probe, warn (stale state) but proceed with available members. Never write pool.json. |
| `lock.rs` | iterate membership.disks for mapper close |
| `add.rs` | accept name=by_id from args, `validate_no_conflicts()` against existing membership (or empty if first add), pre-commit persist, then LUKS format + btrfs add |
| `replace.rs` | look up old in membership, accept new as name=by_id, `validate_no_conflicts()` for new entry, pre-commit persist swap |
| `remove.rs` | pre-commit persist removal to pool.json, then btrfs device delete |
| `remove_missing.rs` | pre-commit persist removal, then btrfs device delete missing |
| `status.rs` | list unpooled disks from membership |
| `doctor.rs` | verify membership by_id paths are block devices |
| `enroll_key_file.rs` | iterate membership for LUKS enrollment |
| `tui/mod.rs` | build UI from membership |
| `main.rs` | shell completion from membership |

Note: `braid add` on a fresh system (no pool.json yet) creates pool.json as part of its
pre-commit persist. This is the normal path — pool.json is born from `braid add`, not
from discovery.

Update `probe_config_disk()` in `probe.rs` to accept `(name: &str, by_id: &str)`
instead of `&DiskConfig`.

## Verification

1. `just test-rust` after commit 1
2. `just test` after commit 2
3. Smoke test:
   - Fresh pool: `braid add disk1=/dev/disk/by-id/... disk2=/dev/disk/by-id/...`
   - Verify pool.json written before LUKS format
   - Reboot → `systemctl start braid-pool.target` → unlock reads pool.json
   - `systemctl stop braid-online` → clean lock + LUKS close
4. Unlock requires authoritative state:
   - Delete pool.json → `braid unlock` fails with clear error
   - Corrupt pool.json → `braid unlock` fails with clear error
   - `braid discover --write` → creates valid pool.json → `braid unlock` succeeds
5. Stale state:
   - pool.json references a disk that's been physically removed → unlock warns, proceeds
     with remaining members
6. Pre-commit semantics:
   - Simulate pool.json write failure → `braid add` aborts before LUKS format
   - Simulate pool.json write failure → `braid remove` aborts before btrfs device delete
   - Simulate pool.json write failure → `braid replace` aborts before LUKS format on new disk
   - Simulate pool.json write failure → `braid remove-missing` aborts before btrfs delete missing
7. Lifecycle:
   - braid-online.service activation failure → wrapper prints WARNING to stderr, command exits 0
   - Pool is mounted and usable despite activation failure
   - `braid lock` → wrapper deactivates braid-online.service → `systemctl is-active` shows inactive
   - `braid unlock` then `braid lock` → braid-online active then inactive (round-trip)
8. Membership conflict validation:
   - `braid add toshiba=/dev/disk/by-id/NEW` when toshiba already exists with different by_id → rejected
   - `braid add newname=/dev/disk/by-id/EXISTING` when that by_id is already under another name → rejected
   - Same checks for `braid replace --new`
9. Regression: all commands read pool.json, not config:
   - `braid lock` iterates membership for mapper close
   - `braid status` shows disks from membership, flags unpooled members
   - `braid doctor` checks membership by_id paths are present block devices
   - Shell completion offers disk names from membership, not config

## Decided: `braid add` syntax

`name=by_id` positional pairs. Supports multi-disk initial RAID1 setup in one command:
`braid add toshiba=/dev/disk/by-id/ata-TOSHIBA wd=/dev/disk/by-id/ata-WDC`
