# Fix stale `ComputationError` example in ADR 014

## Context

ADR 014 (`docs/design/decisions/014-alerts.md`) is the cited authority for anyone
modifying alert computation -- its frontmatter says "Read before modifying alert
computation, monitor, status...". Per AGENTS.md, an authority doc that contradicts
the code is wrong and must be fixed.

Line 84 lists three illustrative examples of indeterminate states that latch a
`ComputationError` and exit 1:

> `e.g. probe failure, parse failure, unmapped device`

The third example is stale. The monitor migrated to keying btrfs device stats by
`devid` (commits `92faea96`, `8e416ca5`, `81c0e165`). A stats row whose devid is
outside the recognized membership set is now **benign**: it is skipped, never
latches a cause, and `braid monitor` returns `Ok`. There is no `UnmappedDevice`
variant in `ProbeError` (`cli/src/probe.rs#ProbeError`). The behavior is pinned by:

- `monitor.rs#stale_mapper_row_no_longer_latches_computation_error` (zero counters)
- `monitor.rs#stale_mapper_row_with_errors_does_not_latch_or_loop` (non-zero counters, no ack loop)
- `alert.rs#unrecognized_devid_with_errors_does_not_alert`

So the ADR's example tells a future reader the exact opposite of the current,
intended fail-open-avoidance design. The user-facing command doc
(`docs/commands/monitor.md:41`) already enumerates the correct set and does **not**
mention "unmapped device" -- the ADR is the lone stale outlier.

## The change

One edit, one line.

**`docs/design/decisions/014-alerts.md:84`** -- replace `unmapped device` with
`mountinfo I/O failure`:

```
- **1** -- alert active (disk health issue OR indeterminate state latched as `ComputationError` -- e.g. probe failure, parse failure, mountinfo I/O failure)
```

Rationale for the replacement wording (all three illustrative examples stay
distinct and accurate):

- `mountinfo I/O failure` is a genuinely indeterminate state that latches
  `ComputationError` -- documented in this same ADR at line 100 ("Any mountinfo
  I/O failure ... surfaces as `ProbeError::MountInfo`, latches `ComputationError`,
  exits 1") and backed by `ProbeError::MountInfo`.
- It matches the canonical enumeration already in `docs/commands/monitor.md:41`
  ("mountinfo read"), keeping the authority doc and the command doc consistent.
- Prefer it over the finding's alternative "btrfs device stats spawn failure,"
  which is just a sub-case of the "probe failure" already in the list (a
  `ProbeError::Cmd`) and would read as redundant.

Keep the list at three terse illustrative examples. Do **not** expand it into a
full enumeration mirroring `monitor.md:41` -- two exhaustive lists would drift.

## Explicitly out of scope (do NOT change)

- **Code comments** at `cli/src/monitor.rs:381` ("previously ... produced an
  `UnmappedDeviceError`") and `cli/src/alert.rs:1314` ("positive replacement for
  the deleted `unmapped_device_is_error_in_alert` test"). These deliberately name
  the old behavior to explain what the regression tests guard -- correct
  historical context, not stale errors.
- **Build artifacts** under `docs/book/html/` that contain the old string. That
  tree is gitignored (`.gitignore:12 docs/book/`) and regenerated by
  `just docs-build`; no manual edit.
- No code change. The code is already correct; this is a docs-only fix.
